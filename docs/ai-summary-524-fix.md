# 0.2.1：AI 总结 HTTP 524 修复

## 证据与原因

2026-09-21 23:31 的 paper-feed.state.json 记录 AI request failed with HTTP 524。已安装 XPI 的 SHA-256 与发布的 0.2.1 一致。原日志未记录失败阶段，无法还原具体批次。检查时缓存共 1000 篇，按 DOI/entry 提交键核实有 55 篇待总结。

原 0.2.1 安装包没有打入本地已有的 AI 重试与最终排版降级实现。接口超时直接终止整轮。这次将相关实现纳入发布，并进一步补上持续超时后的拆批处理。

## 修复

- 筛选请求最多尝试 3 次；持续超时、HTTP 408/5xx 或空内容时，对多篇批次递归拆分，并保持全局论文编号。
- 单篇仍失败则结束整轮，错误说明阶段、批次和论文范围；不修改已提交论文集合、不覆盖已有摘要。
- 401 等不可恢复错误不重试，429 不触发拆批增加请求。
- 最终 AI HTML 排版失败最多尝试 3 次；可恢复错误持续发生时，用已生成的逐篇摘要本地排版，并标明降级。不会把筛选失败当作无相关论文。
- 去掉旧版 40 篇入选截断，保留所有有效筛选结果；兼容 API 数组形式的文本内容。
- HTTP 524 报错保留简明原因；关闭 Zotero HTTP 层隐式长时间重试，由总结流程统一控制尝试次数。

## 验证

新增回归测试先复现持续 524 无法拆批，修改后通过；状态集成测试确认失败不会将待处理论文标为已提交，也不覆盖原摘要。

使用当前用户配置，对 2 篇真实待处理论文进行小样本验证：2 次请求、44 秒，选中 1 篇并正常生成 4077 字符 HTML，无降级警告。未写入 Zotero 状态或摘要文件。详见 ai-summary-live-check.json。

这验证了当前接口的小样本筛选和排版可用，不等于全部 55 篇已重新总结，也不能消除上游服务本身的超时。

安装 paper-feed-v0.2.1.xpi 后重启 Zotero，再运行 AI 总结。

发布验证：独立提交源码副本 66 项测试通过、TypeScript 与构建通过。XPI 内部版本 0.2.1，已检查筛选拆批、局部 HTML fallback 和 HTTP 重试控制标记。完整本地工作区 69 项测试通过。
